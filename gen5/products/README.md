## Purpose

Every sporeGarden product began as a baseCamp paper in gen3. Each crossed the gen3/gen4 boundary differently — some through a citizen science community, some through a faculty lab, some through a creative experiment. This catalog tracks each product's journey from theory through validation to deployment to external science production.

The journey is the same pattern expressed in different soil:

```
baseCamp paper (gen3 theory)
    → Spring validation checks (gen3 proof)
    → Garden seed (gen4 composition)
    → Primal composition + deploy graph (gen4 product)
    → External collaborator engagement (gen5 science)
    → pseudoSpore deliverable (gen5 artifact)
    → New spring validation targets (gen5 feedback)
    → Springs evolve (cycle continues)
```

## The Generational Crossing Points

Each product crossed into gen4 at a different moment. The crossing point is when the primals became infrastructure rather than subject — when the product existed for the user, not for proving the primals work.

### esotericWebb — The Template Crossing (March 2026)

**baseCamp 17** (Game Science) theorized that ludoSpring validation could compose into a real game engine. **baseCamp 18** (RPGPT) built the narrative AI layer. **V4** was the crossing: `GameSession::act()` called primals through PrimalBridge, and the player never knew. Every subsequent product cites esotericWebb as the template: "Where esotericWebb proved the gen4 pattern for creative domains..."

**Key arc**: V1 (standalone YAML) → V2 (PrimalBridge stubs) → V3 (content pipeline, CLI) → V4 (live composition, ludoSpring + Squirrel + petalTongue + rhizoCrypt) → V7 (federation)

**What it proved**: Graceful degradation, dual surface (YAML/Rust), bounded infinite stories, provenance in the game loop, zero-import principle.

### lithoSpore — The Field Deployment Crossing (May 18, 2026)

**guideStone** was a certification concept for self-proving output. **GUIDESTONE_LTEE** mapped it to Barrick's LTEE data. The crossing happened when 4 USB drives landed on a lab bench — 73 science checks, 7 modules, 7 published papers, three-tier validation (Python → Rust → Primal). The field failure (ext4 on Windows) taught the Layer 0-4 model.

**Key arc**: guideStone concept (May 11) → GUIDESTONE_LTEE design → 7-day build → field deployment (May 18) → exFAT fix → pseudoSpore pattern extraction

**What it proved**: Domain-agnostic validation chassis, USB-deployable science, the surface/science/infrastructure three-zone model.

### initioChem — The Citizen Science Crossing (May 2026)

**hotSpring Exp 220** validated CAZyme conformational FEL through GROMACS + PLUMED metadynamics. **pseudoSpore v1.7.0** packaged 190/190 checks into a self-verifying artifact. The crossing happened when Alistaire (ABG citizen science community) received the artifact and typed `./validate` — external science production through a product layer.

**Key arc**: hotSpring Exp 220 (bonded FF + metadynamics) → pseudoSpore v1.6.1 → v1.7.0 (190/190) → ABG Project 3 delivery → initioChem seed (interactive FEL explorer)

**What it proved**: The spore cycle works end-to-end — spring validation → artifact → external collaborator → feedback. First pseudoSpore handoff.

### blueFish — The Retirement Crossing (May 2026)

**wetSpring Track 2** validated PFAS detection with Dan Jones's lab data — FindPFAS 17/17, EPA PFAS ML 14/14, MassBank 9/9 = 40/40 PASS. The crossing took an unexpected form: Jones retired. His technical feedback (NIST standards, EPA 1633A QC, open-source tool gaps, LOQ consistency) became the specification for blueFish as a sovereign analytical chemistry ETL — replacing Chromeleon, MassHunter, Xcalibur with open tooling.

**Key arc**: Jones Lab PFAS collaboration → wetSpring Track 2 (40/40) → Jones retirement → technical feedback as product spec → blueFish seeded → emeritus consulting

**What it proved**: The ecosystem survives personnel transitions. The science validated in gen3 becomes the product specification in gen4 regardless of the collaborator's institutional status.

### helixVision — The Multi-Product Crossing (May 2026, in progress)

**baseCamp papers 03, 04, 09, 10, 21** (BioAg, Sentinels, Field Genomics, coralForge, Sample Provenance) validated the genomics pipeline across 6,656+ wetSpring checks. helixVision was designed as the gen4 product layer. But the NF project revealed something gen4 hadn't anticipated: helixVision alone isn't enough. NF data mining requires helixVision (gene expression) + healthSpring (drug repurposing) + initioChem (conformational dynamics) + coralForge (structure prediction) — the first **multi-product composition** for an external PI.

**Key arc**: baseCamp genomics papers → wetSpring 6,656+ → helixVision conceptual → Gonzales NF project → multi-product composition mapping → first gen5 instance

**What it proves (in progress)**: gen5 requires products to compose with each other, not just with primals. Single-product gen4 is necessary but not sufficient for external science production.
