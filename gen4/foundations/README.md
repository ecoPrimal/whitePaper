## The Unified Lineage

gen4/foundations/ is not a collection of separate projects. It is **one
foundation** — the complete validated scientific lineage produced by gen3
(28 baseCamp papers, 8 springs, 12,510+ checks, 70+ reproduced papers,
12+ faculty and community contacts) — mapped as a unified whole and
extended through NUCLEUS composition with full structural provenance.

Products (helixVision, blueFish, esotericWebb, Patient Records) are
different **focuses** on this foundation. They pull specific threads from
the lineage and present them for different audiences. The foundation is
the root system; products are the fruiting bodies.

projectNUCLEUS focuses on the primals as gen4 deployments — the
infrastructure layer. Foundations focus on the **science lineage** — the
validated knowledge that gives those deployments purpose.

## Why One Foundation, Not Many

gen3 springs reproduce individual papers. The early gen4 instinct was to
create separate "foundations" — one for whole-cell modeling, one for
plasma physics, one for evolutionary biology. But that misses the point.

The science is not separate. Anderson localization (Paper 01) threads
through microbial ecology (03, 04, 05, 06), immunology (12), digester
engineering (16), and plasma physics (07) — it is one mathematical
backbone with many domain applications. The provenance trio validates
game sessions (18, 19) and biological samples (21) and medical records
(22) using the same DAG/certificate/braid machinery. barraCuda's GPU
math powers lattice QCD (07, 10b, 25), protein structure prediction
(10a), environmental monitoring (04, 08), and drug screening (12, 13).

The lineage is interconnected. The foundation must reflect that.

Individual **expression documents** zoom into specific domain threads
(the ABG whole-cell rebuild is the first). But they are views into the
one foundation, not independent projects.

## The Living Repository: `sporeGarden/foundation`

This section of gen4 describes what the foundation **is**. The operational
implementation lives in the `sporeGarden/foundation` Git repository,
which deploys via projectNUCLEUS.

**Foundation is the soil. NUCLEUS is the spore that grows on top.**

| Layer | Repository | Contents |
|-------|-----------|----------|
| Science lineage (this doc) | `whitePaper/gen4/foundations/` | Why the foundation exists, what it validates, how threads connect |
| Operational soil | `sporeGarden/foundation` | Data source manifests, validation targets, fetch/validate scripts, workloads |
| Deployment infrastructure | `sporeGarden/projectNUCLEUS` | Primal composition, deploy graphs, provenance pipeline |
| Dev-team guidance | `wateringHole/` | `FOUNDATION_INTEGRATION_GUIDE.md`, `SEDIMENT_LAYER_MODEL.md` |

### Current State (May 2026)

The `sporeGarden/foundation` repository is live and operational:

- **100+ public data source anchors** across 5 thread manifests (NCBI, UniProt, KEGG, PDB, BRENDA, PhysioNet, DrugBank, ChEMBL)
- **36 validation targets** with published values and tolerances across Threads 1 and 3
- **26 baseCamp papers** mapped in `lineage/BASECAMP_PAPER_MAP.toml` with threads, springs, and data anchors
- **Operational fetch pipeline** (`deploy/fetch_sources.sh`) — successfully fetching and BLAKE3-hashing real NCBI/UniProt/KEGG data
- **Provenance-wrapped validation** (`deploy/foundation_validate.sh`) — 7-phase pipeline adapted from projectNUCLEUS
- **3 initial workloads** for Thread 1 (WCM genome hash, proteome validation, KEGG pathway check)

### The Sediment Layer Model

Each validation run deposits a sediment layer: source data (fetched and
hashed) + computation (dispatched through toadStool) + provenance
(rhizoCrypt DAG + loamSpine commit + sweetGrass braid) + report. Layers
accumulate. Cross-spring reinforcement (same target validated by multiple
springs) produces metamorphic layers. The geological record is permanent,
content-addressed, and structurally auditable.

See `wateringHole/SEDIMENT_LAYER_MODEL.md` for the full model.
See `wateringHole/FOUNDATION_INTEGRATION_GUIDE.md` for spring integration.
