## **1. Overview**

`sweetGrass` is the semantic provenance and attribution layer of the `ecoPrimals` ecosystem. It is a distributed service responsible for creating, linking, and storing verifiable metadata about all data and processes within the network. Its primary function is to answer the question, "What is the story of this data?"

It is the Primal that transforms a collection of disconnected data into a rich, queryable, and trustworthy knowledge graph. It provides the foundation for the `gAIa` knowledge commons and the future economic layers of the ecosystem.

## **2. Core Data Model: The "Braid"**

The fundamental data object in `sweetGrass` is a **Braid**. A Braid is a cryptographically signed, machine-readable document containing semantic metadata and provenance information. Braids are designed to be self-describing and human-readable using the **JSON-LD (JSON for Linked Data)** standard.

### **2.1. Braid Structure**
A simplified Braid for a file generated by an AI model might look like this:

```json
{
  "@context": "https://ecoprimals.io/contexts/sweetgrass-v1.jsonld",
  "@id": "urn:uuid:e8b3cda0-...", // Unique ID for this Braid record
  "@type": "prov:Entity",
  "dataHash": "sha256:f2ca1bb6c7e9...", // Hash of the actual data file
  "mimeType": "application/vnd.alphafold-result.pdb",
  "wasGeneratedBy": {
    "@id": "urn:uuid:a1b2c3d4-...", // Unique ID for the generation activity
    "@type": "prov:Activity",
    "used": [
      {
        "entity": "urn:uuid:b2c3d4e5-...", // The input protein sequence entity
        "role": "ecop:inputModel"
      }
    ],
    "wasAssociatedWith": {
      "@id": "did:key:z6Mk...", // The bearDog DID of the agent who initiated the task
      "@type": "prov:Agent"
    },
    "startedAtTime": "2025-07-15T10:00:00Z",
    "endedAtTime": "2025-07-15T11:30:00Z",
    "ecop:computeUnits": "1.5" // Custom field for economic attribution
  },
  "signature": {
    "type": "Ed25519Signature2020",
    "creator": "did:key:z6Mk...",
    "signatureValue": "..."
  }
}
```

### **2.2. Key Principles of the Model**
- **Based on W3C PROV:** The structure adheres to the W3C PROV-O standard for provenance (Entity, Activity, Agent), ensuring interoperability.
- **Content-Addressable:** The `dataHash` field creates an unbreakable link between the Braid and the data it describes.
- **Cryptographically Verifiable:** The `signature` block ensures that the Braid is tamper-proof and its authorship is non-repudiable, using identities provided by `bearDog`.
- **Extensible Vocabulary:** The `@context` allows for a rich, evolving vocabulary to describe any type of data or activity within the ecosystem.

## **3. Architecture and Workflow**

`sweetGrass` is designed as an event-driven, distributed service that listens to the activities within a `biomeOS`.

1.  **Event Emission:** `toadStool`, as the universal runtime, is responsible for emitting events for significant lifecycle actions (e.g., `activity.started`, `activity.completed`, `entity.created`).
2.  **Braid Generation:** The `sweetGrass` service, running as a privileged Primal within the `biomeOS`, subscribes to these events. When an `activity.completed` event is received, `sweetGrass` gathers the relevant details (input entities, agent, duration) and generates a new Braid.
3.  **Signing by the Agent:** The Braid is then presented to the `bearDog` agent of the user or service that initiated the activity. The agent signs the Braid, attesting to its validity.
4.  **Commitment to `loamSpine`:** Once signed, the Braid is submitted to the `loamSpine` Primal for permanent, immutable storage. This makes the data's story part of the permanent record.

## **4. API and Query Layer**

To make the vast web of Braids useful, `sweetGrass` provides a powerful query API, likely implemented with **GraphQL**.

This API allows any service (especially `gAIa`) to traverse the knowledge graph and ask complex questions:
-   "Show me the full provenance graph for the data with hash `X`."
-   "List all activities performed by user `Y` in the last 24 hours."
-   "Find all datasets derived from the `NCBI_genome_ingest` activity."
-   "Calculate the total `computeUnits` contributed by all agents in the `scienceBiome`."

The API serves as the "storyteller," making the history and context of data accessible and understandable.

## **5. Integration with Core Primals**

-   **`toadStool`:** The primary source of auditable events that trigger Braid creation.
-   **`bearDog`:** Provides the decentralized identifiers (DIDs) and cryptographic keys necessary for signing and verifying all Braids. `sweetGrass` relies on `bearDog` for its root of trust.
-   **`loamSpine`:** The immutable append-only log where all signed Braids are stored. `sweetGrass` is the writer; `loamSpine` is the permanent book.
-   **`gAIa`:** The primary consumer of the `sweetGrass` query API. `gAIa` uses the provenance information to determine the trustworthiness, relevance, and context of the data it reasons over.

## **6. Future Work: The Economic Layer**

While the core `sweetGrass` specification focuses on provenance, it lays the direct groundwork for an economic system (e.g., the conceptual `SunCloud` agent). By recording contributions (`computeUnits`, `storageProvided`) in a verifiable and immutable way, `sweetGrass` provides the raw data needed for a future service to:
-   Implement reward systems.
-   Build user reputation.
-   Create a marketplace for federated compute and storage resources.
